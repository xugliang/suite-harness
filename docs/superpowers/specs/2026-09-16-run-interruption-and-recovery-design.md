# 运行停止与会话恢复设计（2026-09-16）

## 范围与语义

本功能属于 SuiteHarness 底座，不以产品 A/B 的旧接口限制底座设计。现有 `SessionStore.resume()` 是会话快照读取，不是恢复一个正在运行的模型流；已取消的旧 `run_id` 永远保持终态。用户有三种操作：

1. **停止**：在已认证会话中请求停止一个明确的运行，停止意图先持久化，再通知本进程执行器；晚到输出不能作为成功消息、长期记忆或工具续跑检查点提交。
2. **恢复历史**：重连后读取该销售账号/员工有权访问的会话消息，显示取消标记和有上限的部分输出。它只供界面显示，不自动进入下一次模型上下文。
3. **继续任务**：只有旧运行已取消、仍是本会话最新运行、且有可验证的安全检查点时，发起新的、显式关联旧运行的 `run_id`。模型新开一轮，从持久化的完整 ReAct 步骤及标准 tool observation 接续；绝不恢复旧流的字节位置或重开旧运行。其他情况明确返回“请重新提问/先对账”。

首版支持 Web 标准 WebSocket 的指定运行停止、历史和安全续跑；飞书 `/停止` 控制命令只停止有权访问的唯一活跃运行或明确提供的消息 ID，不提供写入/删除审批能力。产品 B 的独立销售 WebSocket 属产品适配层，后续应把已认证销售和客户会话映射到这些底座接口；本设计不把 B 的私有 UI 协议放进底座。

## 底座边界

- `SessionStore` 管理精确 `SessionIdentity` + `run_id` 的运行声明、停止意图、只读执行检查点。SQLite 是服务器参考实现；内存实现用于测试。停止查询不等待长会话锁，并以事务检查活跃声明。`SessionStatus` 仍只是会话最近一次运行的状态。
- `ExecutionRunner` 保留当前按 authenticated scope/principal/run_id 的取消映射；`ActivatedCustomerBundle` 添加底座级取消入口。Runner 只在完整工具批次结束后产生内部 checkpoint 事件，不向模型伪造工具结果。
- `ChannelApplication` 是停止意图观察者及检查点持久化边界。执行中定期查询停止标记；本进程通知 Runner；完成前再次核验标记、源失效水位和运行声明。停止与完成竞争只能落一个 terminal transcript，取消不归档长期 MD 记忆。
- `EnterpriseChannelGateway` 对停止、历史、继续与普通发消息执行同样的身份验证、产品路由、共享会话成员、产品/客户访问检查。Web 帧中的会话、产品、目标 message ID 只作选择参数，永不成为身份声明；飞书控制命令在事件验签/去重/正规化后处理。
- 独立可选的产品 ABC 只提供特殊工作流恢复策略或外部写工具对账；现有产品不必实现新方法。默认恢复策略 fail closed，底座 ReAct 给出安全默认实现。

## 停止状态及并发

运行级状态为 `running → stop_requested → cancelled`，另有 `already_finished / not_found / unsafe_uncertain`。`request_stop` 只有在同身份、未过期、未 finalizing 的运行声明上成功；重复请求幂等。跨进程应用观察 SQLite 持久停止意图，本进程信号取消模型/沙箱/多 Agent 子任务。若停止后 Runner 恰好返回成功，应用在终态提交前把它改为 CANCEL，并丢弃成功内容；完成先提交时返回 already_finished。Web 连接关闭仍会取消其任务，但不会误停其他连接的运行。ACK 后尚未持久化输入的排队任务不能虚构历史，客户端可凭相同消息 ID 重发。

## 安全检查点与续跑

检查点是独立的运行恢复记录，绑定完整身份、旧运行、旧输入与会话上下文、模型路线、工具身份、已完成 observations、预算计数、记忆失效水位、来源版本、提交时间。只保留每个运行最新的**完整模型/工具轮次**；状态大小和存活时间有严格上限。工具结果必须是完整内联 JSON；旧 run 专属大结果 `result_id`、一次性审批凭据不能迁到新 run。

首版可复用的工具只允许受控的底座只读工具白名单，经完整 `ToolIdentity`/effects 校验并保存完整成功结果；`agent.delegate` 即使声明 READ 也属于复合调用，默认不可复用；Bash、MCP、插件写/破坏性工具、未知效果默认不可续跑。只读网页结果按原抓取时间显示，并受短 TTL 限制。旧检查点之后若开始过任何工具调用而未形成新的完整安全检查点，不可续跑。崩溃产生的 uncertain 运行、旧运行已成功/失败、来源水位变化、账号或客户授权变化、模型路线/提示词不兼容，都不可自动续跑。

续跑使用新认证 scope、新 grant，并要求只读执行；原输入、原会话上下文及原 ReAct 状态来自可信持久记录，不接受客户端上传的状态。Runner 从记录恢复 observations、计数及 workflow state；ReAct 将旧运行身份作为受信任的 `resume_of_run_id` 验证，后续工具结果仍作为标准 `tool` message 输入模型。旧审批绝不迁移，之后新工具调用重新走权限和网络检查。用户可始终选择重新提问。

## 错误、历史与测试

历史结果只返回 USER、ASSISTANT 和 CANCEL 显示字段；取消标记可带 bounded partial output，并标为不完整。历史显示 API 不改变默认模型记忆规则：取消/不配对输入不自动纳入新问题。Web 历史及续跑权限在请求当下重新核验；产品 B 销售 A 不能读/停/续销售 B 的客户运行。

测试用真实 SQLite 双实例和重开场景验证：正确/错误身份及会话、重复停止、停止与完成竞争、长时间无 delta 的跨进程取消、取消无晚到成功和 MD 归档、终态 transcript 已写但 checkpoint 未写的崩溃窗、历史重连、完整只读结果在新 run 的标准 tool message 接续、旧 `result_id`/委派/写工具/未完成批次/来源变更/授权变化拒绝、原 run 不重执行。现有多 Agent 子任务在父取消后仍按自己的 claim 终止；不把子任务失败重标为可续跑。
