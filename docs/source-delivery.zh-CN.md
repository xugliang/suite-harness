# 源码交付与扩展边界

框架从 `src` 运行，不要求把 SuiteHarness 安装成 pip 包。依赖库仍需安装。

## 最小开发步骤

1. Linux 服务器使用 Python 3.11 或更新版本创建独立虚拟环境。
2. 安装 `requirements/test.txt` 中的开发依赖。
3. 使用 `PYTHONPATH=src python -m pytest` 验证框架。
4. 产品提供自己的 ASGI（异步服务器接口）工厂，用 `CompanyServerBootstrap` 装配公司身份、产品、渠道和权限。
5. 在 YAML 中配置模型路由、密钥文件路径、沙箱及插件；不把密钥写入源码。
6. 可用 `python deploy/source/run.py <部署文件>` 启动可信产品工厂。A/B 分别建立派生镜像和持久数据卷。

`requirements/server.txt` 是兼容范围，不是可复现锁文件。正式发布应在目标 Linux/Python 版本生成含哈希的依赖锁，并记录基础镜像 digest（内容摘要）。不要把其他公司的部署锁和路径作为框架默认配置。

## 插件装配

插件首先经过来源目录、digest、签名/显式信任检查，再激活。产品贡献值必须实现 `ProductActivator`；其描述加入目录后才解析购买组合。

通过 `plugins.bindings_by_product` 显式选择 memory、knowledge、workflow、reflection、prompt、tools 贡献。服务和工具贡献实现 `ProductContributionFactory.prepare(product)`，返回 `PreparedContribution`；每个产品创建独立实例，资源由 cleanup 回收。工具值为 `ToolContribution(spec, handler)`，仍经过产品声明能力、渠道授权和执行器检查。

省略字段继承产品或框架默认实现。选择不存在或类型错误的贡献将拒绝启动，不静默忽略。模型厂商、MCP 连接和公司渠道继续由各自受控配置/官方适配器装配，不通过任意贡献对象替换根权限。

宿主采用激活时快照，不承诺运行中的服务绑定随插件热替换。更新插件应重建对应产品服务；底层注册表热替换不等于运行时热升级。

默认只为明确配置为可信进程内执行、digest 已固定的插件提供 Python 加载器。签名检查开启但无验证器时拒绝启动；隔离插件必须提供受限启动器，不能降级到不受限子进程。

## 框架与产品边界

框架负责执行循环、会话权威记录、通用记忆、工具安全、沙箱、模型适配、MCP/插件协议和通用渠道适配。客户归属、画像定义、材料提取、画像确认、销售建议、员工功能库、推送选择及公司 UI 属于产品。

产品删除/纠正材料时通知框架使派生对话记忆失效；框架不理解“客户画像”业务字段。保留审计原件不等于继续向模型发送失效信息。

## 干净候选与发布限制

运行 `python tools/build_release.py --output <不存在的候选目录>`。仅复制允许的源码、测试、通用部署和文档；不会复制产品、业务数据、密钥、备份或当前服务器配置。每个文件写入 SHA-256 清单。候选生成不执行 GitHub 发布。

扫描是发布前的辅助门禁，不是完整的机密或许可证审计。发布前仍须人工核查 NOTICE、第三方复制来源、依赖许可证及文档。CI 验证代码，不替代真实模型/飞书供应商契约测试和宿主重启演练。
