# 按需技能（Skill）

框架提供读取和执行前置校验，业务技能属于产品仓库。未配置技能的产品不需要修改，
也不会增加模型调用轮次。该机制不替代工具权限、身份校验、人工审批或业务状态校验。

## 接口与注册

`SkillProvider` 是 ABC（抽象基类）。已实现 `FilesystemSkillProvider`（本地文件）、
`McpSkillProvider`（远端 MCP 工具契约）和默认空实现 `EmptySkillProvider`。
产品通过产品级服务键 `SKILL_PROVIDER` 绑定实现。声明 `required_skills` 的工具要求
Provider 同时提供可信 `static_manifest()`；启动时检查引用，避免运行中发现拼错技能 ID。

本地包的 `SKILL.md` 使用 YAML 元数据：`name`、`description`、`version` 必填；
可通过 `includes` 引用公共说明。普通模型只看简短目录，调用
`suiteharness.skill.read({"skill_id": "product.operation"})` 后才取得完整正文。
文件路径、远端 URL、身份和认证信息均不是模型可传的参数。

## 执行路径

1. 主机使用真实产品、员工和本轮执行身份生成可见目录。
2. 明确命令可用 `CommandSpec.preload_skills` 预加载；自然语言由模型选择读取。
3. 模型网关在最终请求上验证完整正文，并登记该响应所产生工具调用的凭证。
4. 执行器依次检查 Schema、权限和 `ToolSpec.required_skills`，再进入审批和业务工具。
5. 缺少技能时拒绝业务动作，返回可纠正的结构化错误；同批次先读再写不能绕过。

已读正文按当前运行阶段固定；重复预加载不会重复访问 MCP。回执可使用独立阶段，
只提供该阶段说明及本次结果，不沿用其他人的历史。正文不能因预算不足被静默截断；
超限时明确失败。自定义模型网关必须接入 `skills.runtime` 的准备、验证及实际响应登记
接口；未接入时技能依赖工具失败关闭，而非相信外层提示词已传入。

## MCP 的边界

MCP 提供传输与工具调用，不存在本文宣称的“通用原生 Skill 协议”。当前远程实现约定
服务提供 `skills.list`、`skills.read`，部署时固定包、服务、版本、正文摘要及允许资源，
复用现有 `McpClientManager` 的连接、认证和网络限制。远端变更、断线、超时不会自动
回退到另一份说明。接入字段和响应格式见 `src/suiteharness/skills/README.md`。

远端当前使用已配置服务身份；不自动代表员工进行 OAuth 登录。员工可见性仍须由可信
主机访问策略控制；MCP 返回的目录只能缩小部署白名单，不能扩大。不要将远端原始
`skills.read` 再以其他工具名直接暴露，绕过受控读取边界。

## 运维与限制

本地技能文件变更后须重新加载产品；镜像内源码须重建镜像。运行期加载凭证不持久化，
新运行或恢复时重新加载，不自动重放写操作。MCP 适配器已具备模拟端到端测试，
实际远端服务必须独立配置和验证；不配置时本地包不受影响。
