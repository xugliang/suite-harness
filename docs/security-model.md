# SuiteHarness 安全模型

本文依据 `0.1.0` 实际代码说明安全目标、控制点和未覆盖风险。它不是认证报告，也不替代客户公司的威胁建模、渗透测试与合规评审。

SuiteHarness 只面向公司服务器 + Web/飞书，不支持个人部署。一个客户公司默认独立部署；`tenant_id`（租户标识）仍必须进入所有作用域、数据键和审计事件。

## 1. 要保护什么

核心安全目标：

1. A、AB、ABC 组合中，一个产品不能读写另一个产品的私有画像、知识、工作区或工具；
2. 未认证用户不能借客户端自报的公司、产品、角色或主体扩大权限；
3. 模型输出、用户输入、网页或 MCP 返回值不能直接变成宿主进程命令；
4. 每次工具调用必须可回答“谁、从哪个渠道、在哪个产品、调用了哪个精确工具、参数是什么、为何获准、结果如何”；
5. 飞书没有交互审批时保持全局只读，只在管理员白名单目录开放写入/编辑，永不删除；
6. Web 的写入/破坏性动作需要与当前主体、运行和参数绑定的一次性审批；
7. 插件、产品和 MCP 的权限声明只能缩小权限，不能自行签发授权；
8. 失败、超时、重投和停机不能静默重复不确定副作用。

## 2. 威胁来源

框架按以下输入不可信设计：

- WebSocket 帧、飞书事件和用户文本；
- 模型生成的工具名、参数、文本和工作流状态；
- 工具输出、网页内容、DNS（域名解析）结果、代理响应；
- MCP 服务的能力、工具描述、注解、资源和回调；
- 未验证的插件清单、文件和配置；
- 客户产品配置中的任意数据；
- 重放、乱序、重复投递及异常中断。

框架不承诺抵抗已被完全控制的公司服务器、操作系统、Docker 守护进程、数据库管理员或密钥系统。经允许的 `trusted_in_process`（可信进程内）产品/插件也在可信计算基中。

## 3. 身份与作用域

`RequestScope`（请求作用域）绑定：

```text
tenant_id + product_id + [agent_id + session_id]
+ principal_id + channel_id + roles + purpose
+ request_id + correlation_id
```

它只能由服务器在渠道认证和产品路由后构造。客户端不得选择 `tenant_id`、内部 `principal_id`、角色或工具授权。

`ScopePath` 在构造时验证 Root → Tenant → Product → Agent 的层级。运行入口再次确认请求的公司和产品属于当前激活组合。服务使用带类型的 `ServiceKey`，画像只能绑定 Product，Customer360 只能绑定 Tenant。

重要限制：`RequestScope` 是不可变值对象，不是签名能力令牌。同一 Python 进程中的恶意代码仍可伪造对象或直接访问本机资源。因此，作用域可以防止正常集成串线，不能代替进程隔离。

## 4. 产品数据隔离与共享

默认 `customer360.mode=isolated`。用户画像由每个 `tenant_id + product_id` 空间拥有，激活时每个产品都必须绑定画像提供器；同一个存活实例不能被两个产品复用。

实例身份检查只能发现“同一对象复用”。生产适配器还必须确保 A、B 的不同对象不会意外连接同一个无产品前缀的表、索引、对象存储路径或加密密钥。

跨产品只允许 `curated`（策展式共享）：

1. A 在私有空间产生事实；
2. 经可信实体映射把 A 的本地主体关联到公司实体；
3. A 按精确 `A → B → predicate` 规则提交候选；
4. 具备策展角色的主体接受或拒绝；
5. 被接受事实复制到租户级共享空间并保留来源链；
6. B 还要通过自己的消费规则才能读取。

例如允许 A 向 B 共享 `preference.language`，不会允许 B 直接查 A 私库，不会顺带共享其他字段，也不会形成 B → A 的反向边。

## 5. 工具安全决策链

模型和产品不能直接调用处理器。每个 `ToolIntent`（工具意图）进入 Root 拥有的 `ExecutionRunner` 后按顺序检查：

1. 按 Product → Tenant → Root 解析工具；
2. 使用完整 `ToolIdentity`（工具身份：命名空间、名称、来源、版本），不能只凭可碰撞别名授权；
3. 使用 JSON Schema（JSON 结构规则）验证参数；拒绝远程 `$ref` 和 `$dynamicRef`；
4. 核对短时 `CapabilityGrant`（能力授权）的公司、产品、主体、有效期、精确工具和能力集合；
5. 核对运行级 `read_only`（只读）开关；
6. 核对工具效果：读、写、破坏性、外部访问；
7. 执行公司渠道策略；
8. 必要时消费一次性审批；
9. 检查迭代、工具调用、并发、总时长、输入/参数/结果/输出/状态字节预算；
10. 调用处理器并追加结构化审计事件。

破坏性工具始终需要审批，即使自定义策略错误地返回允许。授权在运行开始前由 `ConfiguredGrantIssuer` 按 `(channel_id, product_id)` 模板解析为精确身份，并在运行结束撤销；工具注册的效果若变化，旧模板会失败关闭。

审批绑定完整公司/产品/Agent 路径、主体、运行、调用、工具身份和参数摘要，只能原子消费一次。取消也绑定作用域、主体和运行，不可仅凭 `run_id` 干扰其他用户。

## 6. Web 与飞书权限

| 控制 | WebSocket | 飞书 |
| --- | --- | --- |
| 身份 | 企业 SSO 后短时票据，或注入 OIDC/JWT | 飞书外部用户标识经企业目录映射 |
| 默认授权 | 管理员为产品配置工具模板 | 全局只读 |
| 写入 | 写工具仍走交互审批 | 仅显式开放内置 `suiteharness.fs.write/edit` |
| 路径 | 工作区策略约束 | 只允许配置白名单子目录 |
| 删除/破坏性 | 始终审批 | 永不允许 |
| Bash | 可显式授权，且按破坏性工具审批 | 禁止 |
| 默认 MCP 写工具 | 可按策略与审批授权 | 禁止 |

飞书可写必须同时满足两项：

1. `channels.feishu.writable_roots` 允许目标路径；
2. 对应产品的飞书 `ToolAccessTemplate` 显式列出 `suiteharness.fs.write` 或 `suiteharness.fs.edit`。

任一层缺失即拒绝。飞书模板不能包含其他写工具或任何破坏性工具，文件策略固定 `allow_delete=false`。框架没有内置文件删除工具。

内置 ASGI（异步服务器网关接口）应用的 Web 会话交换路由默认是 `POST /auth/session`。它不接受账号密码或其他正文，而是把浏览器已有的公司 Cookie 或 Bearer（持有者）凭据及经过大小/数量限制的请求头交给部署方 `CompanyHttpAuthenticator`。请求必须带精确命中 HTTPS 白名单的 Origin（网页来源）；认证器返回的公司必须与部署配置一致。认证调用受 `authentication_timeout_seconds` 约束（默认 10 秒、硬上限 60 秒），超时或适配器异常统一返回不泄露细节的 503。成功响应只返回短时 HMAC（基于哈希的消息认证码）Bearer 票据并禁止缓存，不设置 Cookie；寿命配置范围为 30–900 秒，默认 300 秒。WebSocket 在 `accept` 前再次认证票据，Origin 使用同一类精确白名单且禁止通配符；二进制帧被拒绝，文本帧在 Uvicorn 协议层和应用层共用固定 1 MiB 上限，连接并发和消息数也有边界。交互审批只广播给相同公司和主体的连接，并由服务器协调器核验决定。

该路由是“已验证公司登录态 → SuiteHarness 短票”的交换，不是 SSO 登录实现。实际 SSO/OIDC/JWT 验证、Cookie 场景的 CSRF（跨站请求伪造）校验、账号禁用、角色同步和登录审计均由部署方认证器负责；框架只允许 `X-CSRF-Token` 请求头，并不会验证其语义。签名密钥配置至少 32 个字符，但长度校验不等于高熵或安全托管。当前票据也没有 key-id（密钥编号）轮换、多密钥验证、单票吊销、刷新或重放存储；已签发角色快照在短票到期前仍有效。生产应使用密码学随机密钥和短寿命，并在外围补齐轮换、吊销、速率限制和风控。

`/health/live` 只证明 ASGI 事件循环可响应；`/health/ready` 会聚合 Foundation、会话/审计/运行数据库、沙箱、插件、MCP、产品、渠道及可选飞书长连接状态，任何一项失败返回 503，响应只公开 `ok/failed`。Docker daemon 探测在单进程内采用 single-flight，并短暂缓存结果（健康 3 秒、失败 0.25 秒）；隔离区或隔离区加载失败仍在每次请求时优先检查并立即失败，缓存的健康结果不能覆盖它。该缓存只降低探测放大，不是访问控制或抗拒绝服务边界：健康端点应只对编排器/私网监控开放，并在反向代理或服务网格设置独立速率与并发限制。readiness 不是模型厂商、搜索/抓取出口、公司 SSO 或飞书外部 API 的深度探测，部署监控仍须补充这些检查。

飞书 Webhook 对原始请求体先验签，再解密和严格解析 JSON；还检查 verification token。长连接适配面依赖官方 SDK 负责认证、重连和确认。生产必须使用持久化事件去重器，不能只依赖进程内去重。

## 7. 文件系统与路径

工作区按公司和产品布局：

```text
{root}/tenants/{tenant}/shared
{root}/tenants/{tenant}/products/{product}
```

文件工具不接受宿主任意绝对路径，而是通过当前请求的 `WorkspaceToolBinding`（工作区工具绑定）选择产品/共享空间，并按规范化后的逻辑相对路径授权。生产文件操作以已经打开的根目录文件描述符为锚点，逐段使用 `dir_fd + O_DIRECTORY + O_NOFOLLOW`（相对目录描述符打开且永不跟随符号链接）；最终读取再次以 `O_NOFOLLOW` 打开并用 `fstat` 确认普通文件。list/glob/grep 使用不跟随链接的目录描述符遍历，遇到符号链接目录不会进入。

写入和编辑在目标父目录的同一个文件描述符中创建独占临时文件、`fsync` 后相对该描述符原子发布。`overwrite=false` 使用同目录 `linkat` 的原子“不覆盖”语义，不存在“先判断不存在再覆盖”的竞态；替换既不会沿最终符号链接写向外部，也不会因父目录被并发换成链接而离开已经打开的目录。读写、遍历深度、扫描数量、时间及结果大小均受限，文本支持 UTF-8、GBK 和 GB18030。

产品目录是默认边界：每个产品只能读写自己的 product 根。shared 根默认关闭；即使全局启用，也只有列入 `workspace.shared_access_by_product` 的产品可见，并分别取得 `read_only` 或 `read_write`。飞书对 shared 写入还必须同时满足该产品是 `read_write`、飞书路径白名单和飞书工具模板三层条件。这个工作区共享开关与 Customer360 的画像策展共享是两套独立机制，开启其中一个不会开启另一个。

生产启动要求 Linux 提供上述 POSIX 文件描述符能力，不满足即拒绝启动。Windows 仅保留明确非安全边界的开发回退路径；它不能用于生产。目录保护仍依赖可信宿主正确配置根目录、权限和底层文件系统语义。工作区根不可与敏感宿主目录重叠；运维也不应把 Docker 套接字、密钥目录或系统目录挂入产品工作区。

## 8. Bash 与 Docker 沙箱

`suiteharness.shell.bash` 是“写 + 破坏性 + 外部访问”工具，始终通过 `SandboxBackend` 执行，不在宿主 Python 中调用 shell。

生产配置只允许摘要固定的 Docker 镜像，并使用：

- `--read-only` 只读容器根；
- 固定非特权用户 `65532:65532`；
- `--cap-drop=ALL` 移除 Linux 内核能力；
- `no-new-privileges` 禁止提权；
- CPU、内存、进程数、临时盘、时间和输出限制；
- 只挂载当前允许的工作区；
- 默认 `--network=none`，或选择运维预建出口网络；
- 超时、取消或 Docker CLI 异常后按确定容器名强制清理。

生产后端在调用 Docker 前先持久化准确容器名的 active lease（活动租约）；写入失败就拒绝启动，所以不会产生一个未记录的新容器。正常完成或准确名称清理成功后才清除租约。进程硬崩溃、清理失败或结果不确定都会让租约留存并使重启后的后端失败关闭；隔离状态加载失败也拒绝运行。管理员恢复时只能核对/强制移除该准确名称，重新检查容器确已消失且成功清除持久记录后才恢复。该机制不是自动事故处置，仍须调查进程与网络影响。

`LocalDevelopmentSandboxBackend` 是本地开发辅助，不是安全沙箱。只有 `environment=development` 且显式 `acknowledge_unsafe` 才可启用；生产配置拒绝它。Windows 可用于开发；当前经过说明和验收的生产安全基线是 Linux + Docker。生产启动会同时验证 Linux 安全工作区后端，不能在 Windows 上以生产模式降级运行。

Bash 出口不是“配置过 Docker network 就自动供所有产品使用”。当前认证产品必须在 `sandbox.network.allowed_profiles_by_product` 中显式列出请求的 profile；未列出的产品只能保持断网。模型输出的 profile 名不能扩大配置权限。

Docker 隔离的边界是容器和宿主内核。镜像供应链、Docker 守护进程权限、内核漏洞、出口网络和挂载内容仍由公司运维负责。

宿主 product/shared 工作区只能通过准确属主、属组或 ACL 让 UID/GID `65532:65532` 访问，不能使用 `chmod 777`。Docker daemon/socket 通常具有接近宿主 root 的权限，不能挂入任何产品、插件或沙箱容器；推荐使用 rootless Docker 或独立沙箱执行节点。

## 9. 搜索与网页抓取

`web_search` 不抓取搜索结果 HTML：百度千帆使用结构化搜索接口；Microsoft Foundry Bing 使用部署方注入的认证客户端。

`web_fetch` 针对 SSRF（服务端请求伪造）采取：

- 只允许公开 HTTP/HTTPS；
- 阻止私网、回环、链路本地、组播、保留和未指定地址；
- 每次重定向都重新解析和检查；
- 固定允许的 DNS 解析结果，并要求传输层证明真实对端 IP；
- 不继承系统环境代理；
- 限制跳转、响应、压缩、解压和解码后文本；
- 直连、显式公司代理和进程外浏览器工作器分路由。

公司代理或浏览器工作器是新的信任边界：它们必须重复执行或等价保证目标地址策略，不能把任意 URL 转发到内网。PDF 提取和浏览器执行是注入接口，不代表默认已启用。

搜索 provider 和抓取 route 也经过产品级出口参数策略。产品未配置映射时只能使用公司默认值；非默认出口必须明确列入该产品，显式空集合则拒绝默认值。这样 ABC 共用 Root 工具处理器时，C 不能借参数选择只为 A 准备的代理或搜索服务。

网页内容始终是不可信数据，不得作为系统指令直接提升权限。

## 10. 模型供应商与密钥

模型配置只保存 `credentials_ref`（凭据引用），真实密钥来自单独服务器密钥 YAML。配置加载器：

- 只读取显式路径；
- 限制文件大小并拒绝符号链接；
- 严格解析，未知字段失败；
- 不做环境变量插值；
- 在 POSIX 系统检查密钥文件权限；
- 校验公开配置中的引用存在；
- 对验证错误做密钥脱敏。

模型 HTTP 传输不继承系统代理，也不自动跟随重定向。请求、会话与审计不应包含凭据。

Bedrock、Vertex 等云身份需要部署方显式提供服务器凭据。任何厂商的个人 OAuth（开放授权）、个人订阅登录或本地个人模型服务都不在支持范围；Ollama/vLLM 适配器只表示可连接公司管理的服务器端点。

## 11. MCP 安全

MCP（Model Context Protocol，模型上下文协议）连接身份是 `(tenant, product, server)`，不能作为跨产品单例。请求还核对当前操作作用域。

安全规则：

- 首选协议版本 `2025-11-25` 并进行能力协商；
- stdio 服务必须通过沙箱和部署方注入的持久沙箱会话工厂；
- Streamable HTTP 必须使用 HTTPS、显式出口策略和服务器管理的令牌；
- 每个服务的 `max_message_bytes` 默认 4 MiB、允许 1 KiB–64 MiB，`max_stream_events` 默认 256、允许 1–10000；核心会再次检查 stdio 实际行、HTTP 响应头/正文、完整或实时 SSE（服务器推送事件）的单事件大小与事件数，超限失败关闭。HTTP 响应头固定最多 128 项、总计 64 KiB；
- `tools/list` 发现同时受 `discovery_timeout_seconds`（默认 120 秒、硬上限 600 秒）、`max_list_pages`（默认 100、硬上限 1000）和 `max_list_items`（默认 10000、硬上限 100000）约束；重复游标或任何预算超限都让该 MCP 服务启动失败，不能带着不完整工具清单继续运行；
- 远端工具的 `inputSchema` 是不可信输入。注册前递归拒绝可触发本地正则回溯的 `pattern/patternProperties`、可形成递归解析的 `$ref/$dynamicRef`、可能退化为平方复杂度比较的 `uniqueItems` 及会把复杂子 schema 应用于整个数组的 `contains`。schema 最多 512 个节点、32 层；单个组合关键字最多 16 个分支、总分支和 `enum/required/properties` 等集合最多 256 项；带 `items/prefixItems/unevaluatedItems` 的数组会被复制并把 `maxItems` 收紧到 4096，且这个廉价检查排在复杂逐项校验之前。实测未限制的 1024 分支 × 50000 项在 30 秒内仍不能完成，因此这是有意的 MCP JSON Schema 兼容性收缩。`format` 与 `content*` 只作为注解保留，框架不安装 format checker、不解码内容、也不据此访问网络；
- MCP 凭据不能由用户或模型传入；
- 远端工具注解不具备授权效力；
- 工具默认按“写 + 外部访问”注册；
- 管理员只有提供理由的配置才可降为只读或提高为破坏性；
- 工具调用仍经过统一执行器和渠道策略；
- 服务端采样回调可路由统一模型网关，但不能获得 Root 授权；
- URL 引导和任务功能默认受显式功能开关控制。

渠道发现了 MCP 工具不代表渠道获权。唯一权限入口是 `mcp.channel_access.web|feishu.<product>`，默认空即全部拒绝：`allow_servers` 显式选择某服务当前发现的全部工具，`allow_tools` 按服务和远端原始工具名精确选择；同一服务不能同时使用两者。宿主启动时确认精确工具确已发现，签发每次运行的短时授权时再次核对服务、原始名、完整工具身份和能力没有漂移。Web 选中的写入/破坏性工具仍逐调用审批；飞书只能选择最终注册为只读的 MCP 工具，其他效果在授权前拒绝。

框架有 OAuth 元数据/令牌模型及缓存接口，但没有替部署方实现完整发现、发行者验证和密钥托管。

`resume_sessions=true` 时，Foundation 已把持久恢复存储接到 MCP 管理器。存储键绑定 `tenant_id + product_id + server_id + 配置端点 SHA-256`，值只有 `session_id` 与 `last_event_id`，不保存 URL、令牌或认证头；出口策略也不允许把请求 URL 改写到另一端点，避免把游标发给错误服务。每次 request/notification（请求/通知）结束后，包括远端异常路径，管理器都会串行完成 CAS（比较并交换）保存再返回；加载、保存或修订不一致会禁用连接。开启恢复时正常停机只关闭本地传输以保留远端会话，未开启时正常关闭会发送 `DELETE`。这保证的是已记录游标的一致使用，不保证远端 MCP 服务永远保留会话，也不代替服务端幂等设计。

## 12. 插件供应链与生命周期

`suiteharness-plugin.json` 被当作不可信、纯数据清单。发现只接受管理员显式路径且必须位于允许根目录，不扫描目录。制品摘要覆盖稳定排序后的普通文件名、长度与内容；符号链接和特殊文件拒绝，并限制文件数和总字节数。

生产配置要求签名，但框架仅定义 `SignatureVerifier`（签名验证器）接口，部署方必须提供真实密码学实现和可信密钥管理。摘要匹配、签名通过和插件标识允许缺一不可。

清单使用封闭权限词汇，单个贡献权限不能超过插件总权限。依赖图检查版本、缺失依赖、冲突和循环。生命周期先准备全部插件，再校验导出与声明完全一致，最后原子发布；失败反向清理。热替换先准备并发布新版本，再退役旧版本；旧句柄不能注销新贡献。

`trusted_in_process` 插件必须精确列入允许清单，拥有宿主进程权限。`isolated_worker` 和 `mcp` 需要部署方提供隔离启动器/代理；框架当前没有通用安全工作进程实现。

插件 manifest（清单）里的 `config_schema` 在 digest（摘要）、签名和部署 trust policy（信任策略）全部通过前只作为有界 JSON 数据解析，绝不会交给通用 JSON Schema 执行器。建立制品信任后仍与远端 MCP 工具共用同一套受限 schema 策略，再校验部署配置；递归引用、正则、平方复杂度唯一性和超出节点/分支/集合/数组预算的 schema 都使插件发现失败关闭。签名证明来源和完整性，不等于允许任意验证算法占用服务器 CPU。

当前 Python `importlib` 仍通过路径加载可信进程内插件，摘要复核只能缩小、不能从技术上彻底消除“复核后到导入前”的路径替换竞态。框架把最后一次 `assert_current` 放在全局导入锁内并紧邻 namespace 安装/导入；生产部署仍必须让插件根目录及其全部祖先由 root/部署管理员拥有，运行 SuiteHarness 的服务账号和插件代码均无写权限，并以容器只读挂载。若威胁模型包含可同时修改插件根的本地攻击者，必须在下游实现“no-follow 文件描述符复制到服务私有只读快照、复核快照摘要、仅从快照导入”，在此之前不得把路径加载宣称为原子安全。

## 13. 会话、重放与持久化

`SessionIdentity` 包含公司、产品、Agent、会话和持久会话所有者。默认 `share_conversation_sessions=false`，所有者就是当前认证主体，不同用户即使进入同一群聊也不会共用持久历史。

渠道网关在身份认证和确定唯一产品后、创建 `RequestScope` 前，可逐消息调用部署方注入的 `ProductAccessAuthorizer`。它可按内部主体、角色、渠道、conversation 和产品连接公司 IAM/ACL；明确拒绝、异常、超时或返回非严格 `True` 都会失败关闭。产品 ACL 和共享 Web 会话成员 ACL 共用 `channels.authorization_timeout_seconds`，默认 10 秒、最大 60 秒。未注入时的兼容语义是“已认证公司主体可访问已购组合内全部产品”，因此有部门/岗位隔离要求的部署必须注入该接口，不能只依赖前端隐藏入口。

显式设置 `share_conversation_sessions=true` 会产生一个绑定“公司 + 渠道 + conversation + 产品”的 synthetic session owner（合成会话所有者），因此同一会话的授权成员会真正共用持久历史。Web 的 `conversation_id` 可由客户端寻址，必须向 `CompanyChannelRuntime.create()` 注入可信 `ConversationAuthorizer`（会话成员授权器），且每次消息都通过成员 ACL（访问控制列表）；未注入、非成员或授权器失败都会拒绝。飞书 `chat_id` 来自已验签事件，发送者仍要经过公司目录认证；目录调用使用飞书独立的 10 秒默认、60 秒硬上限，异常或超时失败关闭。

共享的是对话上下文，不是工具身份：短时 grant 和 Web 审批仍绑定本次真实 `principal_id`。成员变更、历史可见范围和离职撤销由公司的 authorizer/IAM 保证。

多轮上下文由服务器从可信转录事件重建，不接受客户端自报历史。它只选择成功配对的 user/assistant 轮次；失败、取消和未配对轮次不进入上下文，用户 metadata、附件内容、外部 sender 字段和角色也会被清除。重建同时受扫描事件数、消息数和总字节限制，并标记是否截断。共享会话发送给模型的提示词窗口用 `participant-1` 等临时别名表示其他成员，不暴露其真实 `principal_id`；持久转录和授权审计仍按真实主体记录。

`ChannelApplication` 先持久化用户输入、原子运行 claim 和 `started` 检查点，再签发工具授权并运行。相同消息标识和相同摘要可重放终态；相同标识不同内容会冲突。跨进程只有一个所有者能取得同一 `run_id`，旧所有者在终态写入前还须进入 finalizing（终态落盘）围栏。若崩溃或租约过期发生在开始后、终态前，系统返回不可安全重试的失败，要求运维核对，而不会再次执行工具。

SQLite 会话与产品状态使用事务、修订号 CAS 和幂等键。`storage.session_limits` 对会话数、转录正文/数量、运行 claim 数以及检查点正文/窗口设置硬边界。转录与 claim 是防重复执行证据，达限时拒绝而不静默删除；检查点按最新条数和累计字节裁剪。SQLite 审计公开接口仅追加，采用 WAL（预写日志）及同步设置；这不等于防篡改账本，拥有数据库文件权限的管理员仍可改写文件。

Foundation 独占一个运行数据库连接，并在其中创建通用产品状态、MCP 恢复和 Docker 清理隔离清单；渠道组合器应复用这个连接创建飞书去重。通用产品状态存储拒绝明显的审批凭据字段，但不能替代部署方的数据分类和脱敏。画像、知识和 Customer360 的生产存储仍不是这张通用状态表自动提供的能力。

## 14. 审计与隐私

审计事件记录决策和工具调用上下文，但部署方仍要决定：

- 哪些参数/结果要脱敏；
- 数据保留与删除期限；
- 审计读取权限；
- 日志完整性、外部归档和告警；
- 个人信息、商业秘密和跨境数据要求；
- 模型厂商请求日志策略。

不要把密钥、审批令牌、完整敏感文档或未脱敏模型上下文写入普通应用日志。

## 15. 当前不覆盖的风险

`0.1.0` 尚未提供：

- 完整企业 SSO/IAM（身份与访问管理）、飞书目录和账号离职联动；
- 高可用分布式数据库、授权/审批协调、集群锁和全局限流；
- 完整网络边界设施、服务网格、WAF（Web 应用防火墙）和机密管理系统；
- 产品画像/知识/Customer360 的通用生产存储；
- 通用插件隔离工作进程与密码学签名验证器；
- 预配置的全局 ASGI `app`、命令行脚本、完整公司服务镜像和编排基线；框架已有需要部署方注入可信适配器的公司 ASGI 应用与 Uvicorn 便捷入口，仓库镜像仍只有 Bash 沙箱参考；
- SSO 认证调用的熔断/分布式速率限制、短票多密钥轮换与单票吊销（框架已有认证调用硬超时）；
- 生命周期回调的强制超时和同进程恶意代码隔离；
- 审计防篡改、数据保留和行业合规模板；
- 全部模型厂商/版本/地区的生产契约认证。

进程内能力授权、审批、工具注册和交互审批协调器不适合直接横向扩展。SQLite 参考实现更适合单公司单服务器；多实例部署需替换为共享、事务化、可审计的实现。
